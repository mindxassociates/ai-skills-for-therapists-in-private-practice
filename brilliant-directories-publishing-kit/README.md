# Brilliant Directories Publishing Kit

Publish directory and SEO landing pages on **Brilliant Directories** without the two failures that plague this work: pages that go live as paraphrases of the approved copy (with invented provider names, credentials, and fees), and pages that go live still flagged `noindex, nofollow` so search engines never see them.

## What you get

- **A hidden-first publishing flow** — every new page is created as Only Allow Members, filled by wholesale body replacement from an approved styled source file, verified on the live URL, and only then flipped public.
- **Exact live verification, not trust** — the provider-card list compared name-by-name against the expected ordered list, at least 3 exact source sentences probed character-for-character, hreflang targets checked character-for-character, structural negatives, the SEO meta description checked separately, and structured data parsed on the served page.
- **The noindex trap, cleared in the only order that works** — flip to Public first (the checkbox is disabled while a page is protected), then uncheck Apply NoIndex, NoFollow, Save, Refresh Live Site, and confirm the live robots meta reads `index, follow`.
- **An editor-failure stop rule** — when Code View or saving becomes unreliable, you stop at the second dead end and hand over a packet, instead of shipping pages stored as escaped text or wiped empty.
- **A monthly sweep** that re-checks every live page against your roster so drift gets caught.

## Who this is for

Solo and group practices whose directory / landing pages run on Brilliant Directories — especially practices publishing many pages (states, specialties, payers, cities) in more than one language, where a single paraphrased batch or a batch of noindexed pages does real damage to referrals and search visibility.

## How to use this kit

Hand the **whole folder** to your AI agent and say:

> "Publish these Brilliant Directories pages using this kit. Start with the setup interview in SKILL.md — don't create anything until I've answered."

Routes: native skill support (install the folder) / coding-workspace agent (point it at `SKILL.md`) / chat-only agent (upload all `.md` files, paste the prompt from `PROMPT.md`).

## Boundaries

- **The source file wins.** The agent never rewords, shortens, or regenerates approved copy, and never invents a provider, credential, fee, or panel. If exact copy proves impossible, it stops and reports.
- **Verification is independent.** Whoever (or whatever) created the page does not get to be the only checker. A page is done when the named live checks pass — not when a gate report says they did.
- **Your accounts stay yours.** The agent works in your Brilliant Directories admin and your file storage, in sessions you sign in to. No credentials in the kit, none in chat.
- **Hidden until proven.** A page that hasn't passed stays Only Allow Members. There is no "publish now, fix later."
