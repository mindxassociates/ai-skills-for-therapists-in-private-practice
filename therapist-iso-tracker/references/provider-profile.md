# Provider Profile — Template

One block per provider who may be recommended. A solo practice has one block. A group practice has one block per provider, or may replace this file with a pointer to a roster spreadsheet (see the Group practice note at the end).

Delete every field that does not apply rather than leaving a guess in it. A blank field means "not documented" and the matching rules will treat it that way. Never fill a field from memory of a website bio alone — use facts you are willing to stand behind in a public referral thread.

Copy the block below for each provider.

## Group practice note — roster spreadsheet option

If your practice already keeps a roster sheet, you can keep it as the source instead of duplicating blocks here. Then this file should say, in full:

- The spreadsheet name and ID, the tab name, and the range to read.
- A column map written from the actual header row (provider name, credentials, states licensed, specialties, modalities, ages served, types of client, profile URL, private pay rates, sliding scale, contracted panels, accepting new clients, and a notes column for ISO-specific guidance such as sliding scale minimums and exclusions).
- An instruction to re-read the header row on every scan, because columns shift.
- The same rule as the template: only what the sheet documents may be claimed.

Whether the source is this file or a sheet, there must be exactly one source of truth. Two sources that disagree produce wrong drafts.

## Keeping this file true

Update this file and `matching-rules.md` together whenever any of these change: licenses, panels or billing route, rates or sliding scale minimum, accepting status, availability, specialties or modalities, or a do-not-recommend exclusion. After each update, tell the user what changed in plain language.
